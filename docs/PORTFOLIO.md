## 1. 프로젝트 개요

**GitHub 공개 리포 URL 하나만 넣으면, 시크릿 유출·라이선스·한국 규제 준수를 진단하는 오픈소스 클리닉입니다.**

바이브코딩으로 만든 서비스들이 놓치는 한국 법적 책임, 즉 위치정보 사업 신고, 개인정보처리방침, 통신판매업 신고, AI 생성물 고지 같은 항목을 리포 코드에서 역추적해 진단합니다. 2026 SCNU OSS·AI 해커톤 고급 트랙 출품작입니다.

이 프로젝트의 핵심 원칙은 하나입니다. **탐지는 정적분석(gitleaks, semgrep)이 하고, LLM은 해설만 한다. LLM은 finding을 추가·삭제·수정할 수 없습니다.** 점수와 판정은 결정적 코드가 내리므로, LLM을 껐다 켜도 결과가 변하지 않음을 실측으로 증명했습니다.

**왜 이 프로젝트인가.** 해외 오픈소스 진단 도구는 시크릿과 라이선스는 잘 잡아주지만, 한국 법령이 요구하는 사업자 책임은 찾아주지 못합니다. 위치정보법상 신고, 개인정보보호법상 처리방침 게시, 전자상거래법상 통신판매업 신고, AI 생성물 고지 의무 같은 항목은 코드와 문서에 흔적이 남기 때문에, 정적분석 룰로 역추적할 수 있습니다. 리포닥은 이 간극을 노린 도구입니다.

**진단 결과의 형태.** 스캔이 끝나면 건강 점수 0~100과 등급, 보안·규제·라이선스 3축 breakdown, 파일·라인·조문 링크가 붙은 finding 목록, 룰별 한국어 해설, 개인정보처리방침 초안(18목차)이 제공됩니다. 결과는 뱃지 SVG와 통계 카운터로 외부 공유도 가능합니다.

## 2. 기술 스택

| 영역 | 기술 | 비고 |
|---|---|---|
| Backend | Python 3.12, FastAPI, SQLAlchemy 2, Alembic, pydantic-settings | pytest + coverage **80% 게이트**, ruff |
| Frontend | Next.js 14 static export, TypeScript, Tailwind | Playwright E2E, 모바일 375px 대응 |
| Infra | docker compose | worker 격리: uid 10001, read_only, tmpfs, cap_drop ALL / PostgreSQL 16 SKIP LOCKED 큐 / Caddy 리버스 프록시 |
| 분석도구 | gitleaks 8.30.1, semgrep 1.176.0 | 커스텀 한국 규제 룰 11개, 버전 핀 + sha256 검증 |
| LLM | OpenRouter GLM-5.3-flash | json_schema strict, 인용 검증, 수치 필터 |
| CI | GitHub Actions 7잡 | 커버리지 게이트 80%, CI 가드 스크립트 |
| 오케스트레이션 | opencode 멀티에이전트 | 19개 구현 워커 + 3종 리뷰 배터리 + 4종 최종 검증, 모든 단계 실측 증거 |

**스택 선택 이유:**

- **PostgreSQL을 큐로**: 별도 메시지 브로커 없이 SKIP LOCKED로 작업 클레임을 해결해, 단일 docker compose 스택으로 전체 시스템이 돌아갑니다. t3.small 한 대에서 돌아가는 것이 배포 전제였습니다.
- **semgrep 커스텀 룰 11개**: 한국 규제 신호(위치 좌표 처리, 개인정보 처리 문구, 통신판매 고지 등)를 YAML 룰로 정식화했습니다. 룰은 데이터이므로 PR로 누구나 추가할 수 있고, 코드 수정 없이 진단 범위가 넓어집니다.
- **static export**: 프런트에 서버가 필요 없는 구조로 만들어, Caddy가 정적 파일만 서빙하면 됩니다. 운영 대상을 API 컨테이너 하나로 줄였습니다.
- **json_schema strict**: LLM 응답을 스키마로 강제하고, finding_id 인용 검증과 수치 필터로 환각이 결과에 섞이지 않게 이중으로 막았습니다.

## 3. 핵심 설계 결정

**① 탐지와 해설의 분리, LLM 토글로 무대 증명**
점수와 finding은 gitleaks·semgrep·결정적 스코어링만으로 산출하고, LLM은 각 finding의 한국어 해설만 붙입니다. LLM 토글을 끄면 점수와 건수가 1건도 변하지 않음을 실측으로 증명해, "AI가 결과를 조작한다"는 의심을 구조적으로 차단했습니다. LLM 호출이 실패해도 스캔은 정상 완료(status=skipped)이고, 무효 키 입력 시에도 3.5초 만에 done에 도달하는 것을 실측했습니다.

**② 하드닝 클론**
심링크 차단, 용량 사전검사, 3,000파일 상한, 그리고 리포 측 ignore 파일(.semgrepignore 등)의 강제 삭제를 적용했습니다. 악성 리포가 스캐너를 무시하거나 점수를 위조하는 벡터를 사전에 막은 설계입니다. 실제로 심링크가 실체화되는 결함을 실측으로 발견하고, git 서브프로세스마다 하드닝 플래그를 반복 적용해 재발을 막았습니다.

**③ 결정적 점수**
법령 수치(예: 과태료 금액)를 코드·UI 어디에도 쓰지 않는 원칙을 프로젝트 전체에 적용했습니다. 수치는 동결된 규제 카탈로그에만 존재하고, 코드는 신호를 조합할 뿐입니다. 법령 개정 시 코드 수정 없이 카탈로그만 바꾸면 됩니다. 최종 스코프 감사에서 "구현이 법령 수치를 저자한 흔적 0건"을 grep으로 입증했습니다.

**④ 접근 제어**
owner_token 기반 스캔 조회, XFF 기반 요청 한도, 시크릿은 앞 2자만 마스킹해 원문을 저장하지 않습니다. 스캔 리포트 파싱 직후 시크릿 원문을 삭제하는 경로도 코드로 고정했고, 토큰 비교는 상수 시간 비교(compare_digest)로 처리했습니다.

**⑤ CI 가드**
테스트 파일 삭제가 추가보다 많으면 CI가 막고, 잠금 파일(package-lock 등)의 author를 검사합니다. 에이전트가 테스트를 지워 커버리지 게이트를 회피하는 것을 기계적으로 차단합니다. PR 크기 상한(400줄·12파일)도 guard 잡에서 강제합니다.

**⑥ 멀티에이전트 실행 운영**
동결 플랜 + 단계별 게이트 + 축소안(폴백)을 사전에 문서화하고, 19개 구현 워커와 3종 리뷰 배터리(보안·테스트·스펙), 4종 최종 검증(플랜 감사·코드 리뷰·실 QA·스코프 감사)을 돌렸습니다. 모든 단계에 실제 명령과 출력이 담긴 증거 파일이 남습니다.

## 4. 시행착오와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| Next.js static export × Caddy file_server에서 /scan 딥링크 404 | 정적 export는 /scan.html로만 존재 | Caddyfile에 try_files {path}.html 추가 |
| gitleaks GitHub latest/download 404 | 버전명 에셋 경로 불일치 | 버전 핀 + 공식 checksums.txt sha256 검증 |
| semgrep exit 1이 CI 적색으로 처리됨 | exit 1은 "발견건 있음"이지 에러가 아님 | 종료코드 매핑 사전 처리 + 회귀 테스트 |
| GLM-5.3-flash가 빈 응답 반환 | 추론 모델이 4k max_tokens를 reasoning으로 소진 | reasoning exclude + 헤드룸 (OpenRouter 비공식 엔드포인트 한정) |
| semgrep 룰 ID 매칭 실패 | 1.176.0이 check_id에 디렉터리 prefix 부착 | rsplit 정규화 후 비교 |
| read_only 컨테이너에서 semgrep 크래시 | 임시디렉터리 확보 불가 | HOME=/tmp + tmpfs /tmp 마운트 |
| Caddyfile 'email' 지시문 무효 | 유효 지시문 아님 | 'tls <email>'로 교정 (caddy:2 실측 매트릭스) |
| CI 커버리지 80% 게이트 vs 0테스트 시작 | 게이트가 처음부터 적색 | worker 스텁 + 조기 테스트 작성으로 흡수 |
| WSL2 stale session에서 docker 소켓 권한 거부 | 그룹 추가가 구 세션에 반영 안 됨 | 임시 chmod + 새 세션 전환 |
| ruff format 드리프트 (F3 QA 발견) | 7파일 컬럼 조인 차이 누적 | 즉시 수정 커밋 (cfa2f2f) 후 재검증 GREEN |

**이 시행착오들이 남긴 것:**

- 종료코드 매핑과 try_files 같은 교정은 모두 **회귀 테스트나 설정 검증으로 고정**했습니다. 같은 실수를 두 번 하지 않는 구조가 목표였습니다.
- GLM 추론 모델의 토큰 소진 문제는 OpenRouter 비공식 엔드포인트 한정 동작이라, 해결책과 그 전제를 커밋 본문에 기록해 나중에 재현할 수 있게 남겼습니다.
- F3 QA에서 발견된 포맷 드리프트는 "검증 전용 태스크는 수정하지 않는다"는 규칙대로 오케스트레이터 결정을 거쳐 수정 커밋으로 해소됐고, 수정 후 전체 배터리를 재실행해 ALL-GREEN을 재확인했습니다.

## 6. 개발 프로세스: 멀티에이전트 오케스트레이션

이 프로젝트는 사람이 코드를 한 줄씩 쓰는 대신, **동결된 스펙을 에이전트들이 실행하도록 설계**했습니다. 채용 담당자분께서 가장 궁금해하실 부분이라 과정을 따로 정리합니다.

| 단계 | 내용 | 결과 |
|---|---|---|
| 동결 | 스펙·플랜·규칙 문서를 먼저 얼리고 사람만 수정 가능하게 잠금 | 이후 에이전트의 스펙 이탈 0건 (F4 입증) |
| 구현 | 19개 구현 워커가 투두 단위로 실행, 투두당 1커밋 | 커밋 23개, 각 커밋에 근거 ⑥ 기록 |
| 리뷰 | 보안·테스트·스펙 3종 체크리스트 배터리 | 차단 0건, 권고 2건 |
| 최종 검증 | 플랜 감사·코드 리뷰·실 QA·스코프 감사 4종 | 전부 통과, 결함 1건 발견 후 수복 |

**운영 원칙 세 가지:**

- **게이트가 없으면 진행 없음**: 각 투두는 수용 기준을 실제 명령과 출력으로 통과해야 다음 단계로 넘어갑니다. 통과하지 못하면 BLOCKED 아티팩트에 원인과 언블록 경로를 문서화합니다.
- **축소안을 미리 문서화**: 외부 키가 없으면 실측할 수 없는 항목을 미리 분류해, 코드와 테스트가 완성된 상태로 게이트만 문서화해 두었습니다. 나중에 키가 들어오면 재실행 한 번으로 언블록됩니다.
- **증거가 곧 산출물**: 모든 태스크가 명령과 출력을 증거 파일로 남겨, "했다"가 아니라 "이렇게 확인했다"를 남깁니다. 최종 감사는 이 증거를 전수 재확인하는 방식으로 진행됩니다.

## 7. 아키텍처 요약

```
[브라우저]
   │ HTTPS
   ▼
[Caddy 리버스 프록시]
   ├─ /        → Next.js 14 static export (정적 파일 서빙)
   └─ /api/*   → FastAPI (X-Forwarded-For 전달)
                    │ 스캔 요청 INSERT (status=queued)
                    ▼
              [PostgreSQL 16]  ◀── 2초 폴링 (SKIP LOCKED) ── [worker]
                                                     uid 10001 · read_only · tmpfs · cap_drop ALL
                    ├─ preflight: GitHub API 사전 검사
                    ├─ 하드닝 클론 (심링크 차단 · 용량/파일수 상한 · ignore 삭제)
                    ├─ gitleaks (시크릿) + semgrep (커스텀 룰 11개) + 매니페스트
                    ├─ 결정적 스코어링 → findings 저장 → UI 부분 노출
                    ├─ LLM 한국어 해설 (실패해도 스캔은 done)
                    └─ 리포트 저장 → done
```

**흐름의 특징 세 가지:**

- **부분 결과 선노출**: 정적분석이 끝나는 즉시 finding과 점수를 UI에 먼저 보여주고, LLM 해설은 뒤따라 채워집니다. 사용자는 LLM 지연을 기다리지 않습니다.
- **worker 완전 격리**: 외부 입력(리포 코드)을 만지는 worker는 uid 10001로 실행되고, 루트 파일시스템이 읽기 전용이며, 모든 커널 기능이 제거되어 있습니다. 악성 리포가 컨테이너를 탈출할 여지를 최소화합니다.
- **SKIP LOCKED 큐**: PostgreSQL을 그대로 작업 큐로 쓰고, 여러 worker가 동일 스캔을 중복 클레임하지 않도록 SKIP LOCKED로 잠급니다. 별도 메시지 브로커 없이 단일 compose 스택으로 전체 파이프라인이 돌아갑니다.

## 8. 배운 점

**동결 플랜 + 게이트 운영의 가치를 몸으로 배웠습니다.** 스펙을 먼저 얼리고 각 단계에 수용 기준과 게이트를 걸면, 19개 워커가 동시에 일해도 스펙 이탈이 0건이었습니다. F4 스코프 감사가 "Won't 목록 구현 흔적 0건"을 기계적으로 입증한 것이 그 증거입니다.

**"동작할 것이다"는 금지이고, 실측 증거가 문화였습니다.** 모든 태스크가 실제 명령과 출력을 증거 파일로 남겼고, 덕분에 최종 QA에서 발견된 ruff 포맷 드리프트도 원인 유입 지점까지 추적해 18줄 차이로 즉시 수복했습니다.

**사전 적대 시뮬레이션 10회가 실제 결함을 상당수 예방했습니다.** static export 딥링크 404, semgrep 종료코드 해석, 커버리지 게이트와 0테스트의 충돌은 모두 시뮬레이션 단계에서 사전 식별되어 구현 전에 흡수되었습니다. 배포 후에 발견했으면 훨씬 비쌌을 문제들입니다.

**에이전트를 신뢰하되 검증으로 묶었습니다.** 19개 워커에게 구현을 맡기면서도, 동결 문서 무변경·법령 수치 미저작·시크릿 원문 0건 같은 절대 규칙을 grep 기반 감사로 사후 입증했습니다. 자동화와 통제가 대립하지 않고, 통제가 자동화를 가능하게 만든다는 점을 확인한 프로젝트였습니다.

**남은 과제.** 스펙상 남은 단계는 EC2 공개 배포(HTTPS URL, 재부팅 복구), 공개 리포 10개 기준 룰별 정밀도 측정, 데모 영상과 v1.0 릴리즈입니다. 코드와 테스트는 완성된 상태라, 배포 인프라 작업이 앞으로의 과제입니다.
